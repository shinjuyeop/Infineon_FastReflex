## Historical and canonical execution

The M1 golden file `golden_outputs/runtime_chain.npz` was generated by stacking
all 121 `[20,80]` windows and calling each PyTorch GRU once with input shape
`[121,20,80]`. That file is retained byte-for-byte as historical M1 evidence.

The deployment reference is now
`golden_outputs/deployment_runtime_chain.npz`. Each causal endpoint is evaluated
by an independent `[1,20,80] float32` invocation for each member. Every invocation
starts from a zero GRU hidden state; there is no cross-window state. Member logits
and softmax compute remain Float32, member probabilities are promoted to Float64,
and the three-member mean is Float64. Batch-1 is canonical because the E84 control
loop receives one new causal endpoint per millisecond.

## Numerical variability

Repeated canonical batch-1 execution was bit-exact. A deterministic sweep over
batch sizes `1,2,3,4,5,7,8,16,32,64,121` produced the following maximum absolute
differences from batch-1:

| Layer | Sweep maximum | Historical batch-121 |
|---|---:|---:|
| member logits | `2.9802322387695312e-6` | `2.9802322387695312e-6` |
| member Hazard probability | `5.960464477539062e-7` | `5.960464477539062e-7` |
| ensemble Hazard probability | `2.7318795520203665e-7` | `2.682209014892578e-7` |

Every swept execution produced exact threshold crossings, consecutive counts,
`REFLEX_REQUIRED`, and reflex onsets. The logit discrepancy is therefore inherent
to faithful Float32 execution order/batching and is not by itself a semantic model
mismatch.

## Accepted parity contract

| Quantity | Absolute tolerance | Relative tolerance | Other requirement |
|---|---:|---:|---|
| preprocessing and model windows | `1e-6` | `1e-6` | exact shape and dtype |
| member logits | `4e-6` | `0` | exact `[3,121,2]` evidence shape and Float32 dtype |
| member Hazard probability | `1e-6` | `1e-6` | exact shape and Float64 storage dtype |
| ensemble Hazard probability | `1e-6` | `1e-6` | exact shape and Float64 dtype |
| threshold/persistence/decision | n/a | n/a | exact equality |

The preprocessing and probability bounds retain the reviewed M1 contract. The
logit bound is separated because a relative tolerance is ill-conditioned near a
zero logit and valid Research batching already spans `2.9802322387695312e-6`.
`4e-6` is the next explicit decimal bound above that Research-side envelope; it
was not derived by rounding the Deployment failure upward.

Threshold comparison remains inclusive `probability >= 0.99`. Persistence remains
five consecutive 1 ms samples with reset on failure and immediate deassertion.
Threshold crossing, consecutive count, `REFLEX_REQUIRED`, and reflex onset must
all match exactly even when continuous values are inside tolerance.

## Threshold sensitivity

The nearest canonical ensemble probability is `0.9909300009409586`, a margin of
`0.0009300009409586307` above the threshold. The closest below-threshold margin is
`0.0021402939160665158`. At the nearest sample, the ensemble tolerance permits
`1.9909300009409586e-6`, so the observed margin is `467.118854` times larger.
The frozen evidence therefore has substantial separation from the decision
boundary under this Float contract. This does not prove that arbitrary future
inputs or INT8 outputs have the same margin; M3 must measure and report those
risks separately.
